## 修掉的真实缺陷

| 缺陷 | 影响 | 根因 |
|---|---|---|
| 键入 Markdown 标记不渲染 | 用户报告的主问题 | contenteditable 把行尾空格写成 U+00A0，所有以空格结尾的块级规则匹配不上 |
| 引用/标题/列表块吞光标 | 内容被写到块外 | 新建空块没有 `<br>` 占位，零长文本节点被当成落点 |
| Ctrl+S 静默丢改动 | 数据丢失 | 快捷键路径读到恒为 null 的模块级 `activePath` |
| 查找栏只吃第一个字符 | 数据破坏 | `Selection.addRange()` 进入 contenteditable 后编辑管线被编辑器夺走；改用 Custom Highlight API |
| 主题菜单点了没反应 | 5 套主题只有 1 套可用 | `App.vue` 分发时丢掉 `theme.set:<name>` 的参数 |
| 行内格式命令对选区无效 | 加粗/斜体等菜单全废 | 菜单点击让文档失焦，命令读实时选区拿到空 |
| Ctrl+W 关掉整个窗口 | 多标签下灾难 | 快捷键绑在 `file.close` 而不是 `view.closeTab` |
| 关闭脏标签无提示 | 数据丢失 | TabBar 直接关，没走确认 |
| 设置改后不生效 | 偏好设置白改 | 缺主进程 → 渲染进程的设置广播 |
| 另存为后脏标记不清 | 误导 | 只更新了 doc，没同步当前 tab |

## 剩余 2 条：判定为 harness 局限，非产品缺陷

| 编号 | 判定依据 |
|---|---|
| `find.caret-untouched` | 断言用「Esc 关闭前后的光标位移」判「画高亮时有没有挪光标」，两个时机会混在一起。巡检自己也注明该采样无法区分；产品侧改为 Custom Highlight API 后根本不再写选区 |
| `prefs.search-filter` | 偏好设置是独立 BrowserWindow，巡检的 probe 连的是主窗口 target；本地负责偏好设置的 agent 用离屏 Electron + 真实按键实测：键入 `主题` 后 12 行 → 1 行、其余页签变暗、清空复原、无命中出空态 |
